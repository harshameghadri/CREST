- Fixed: the exact kNN search no longer depends on the offset of the embedding. Neighbours were chosen from float32 expanded distances, so an uncentred embedding (a shifted `use_rep`, or raw arrays given to `knn_graph` / `knn_query`) lost most true neighbours as the offset grew (recall 0.99, 0.44 and 0.006 at offsets 100, 1,000 and 10,000 on a 50-column test embedding). Coordinates are now centred in float64 and candidates are compared by exact distance.
- Fixed: `pp.neighbors`, `knn_graph` and `knn_query` raise `ValueError` naming the first affected row when the data contain NaN or infinite values; before, such a row became the nearest neighbour of almost every cell.
- Fixed: `knn_query`'s approximate search probes the inverted lists nearest to each query rather than the lists around the query's own bucket, so shifted or off-manifold queries keep their recall.
- Changed: above 20k cells the approximate neighbour search probes more inverted lists as the data set grows (`max(20, ceil(1.5 * sqrt(n_lists)))`), so its recall no longer falls with the number of cells; neighbour sets above 20k cells change. `pp.neighbors` warns when it switches to this search by itself and records `knn_method`, `nprobe` and `n_lists` in `uns["neighbors"]["params"]`.
