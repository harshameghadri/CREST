- Benchmark protocol: the primary endpoint is the end-to-end process wall time including the imports (the sum of the step timers is secondary; start-up, import and untracked time are reported per tool), per-step comparisons use fused stages, and steps that get slower with more threads (at least 1.5x and 10 s) are listed. Every run records the numba threading layer and thread counts it actually had.
- Benchmark protocol: the thread grid is 1, 2, 4, 8, 16, 32, 64 and configurable, every run is pinned the same way (physical cores first, SMT siblings recorded), an untimed tuning pilot chooses thread settings for both tools with the same budget, unpinned and default-settings controls are kept out of the statistics, runs on a busy host are re-run once and then flagged, and the summary fails when a required result file is missing.
- Benchmark datasets: MTX sets are converted with scipy instead of CREST's reader and every converted file is verified count for count against independent readers; scaling series are seeded random subsamples of real datasets, with the synthetic sets as a labelled supplement; `bench/paper/PREREGISTRATION.md` is the draft template of the pre-registration.
- Documentation: removed the bootstrap-interval statement from the benchmark page and took the R and DESeq2 versions from the recorded environment.
